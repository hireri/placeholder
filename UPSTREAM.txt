Serafin desktop: where the code comes from
==========================================

Metrolist (MetrolistGroup/Metrolist, GPL-3.0) is a source of code, not a build dependency. Nothing is
compiled out of a submodule any more: what we use is vendored into this repo and is ours to edit.
Keep a clone of Metrolist next to this repo for reference, and port from it by hand.

Vendored from Metrolist v13.7.0 (commit e6fea3b), unmodified at the time of copying
  innertube/src/main/kotlin    upstream's :innertube module (YouTube API wrapper, models, pages)
  upstream/src/main/kotlin     lyrics providers (lrclib, kugou, paxsenix, betterlyrics, lyrics/), the Last.fm client,
                               preference keys (music/constants), InnerTubeXPlayer, PoTokenResult
  gradle/libs.versions.toml    version catalog; gradlew and gradle/wrapper come from there too
Our own code
  shims/      source-compatible stand-ins for the Android/Timber/DataStore symbols the vendored files touch.
              Now that the files are ours, prefer editing them to remove the dependency over growing a shim.
  upstream/src, daemon/   adapters and the Ktor HTTP API on 127.0.0.1 (random port + per-run token),
              credential store, YouTube/Spotify/Last.fm auth, services.
  client/     Rust: serafin-login (wry popup) and serafin (the app, egui).
Still a submodule
  vendor/bitchord   BitChord's Spotify library, compiled in place (see bitchord/build.gradle.kts); Dependabot bumps it.

Upstream moved on
  Metrolist v14 is a Kotlin Multiplatform rewrite (shared/, desktopApp/, androidApp/); the :innertube and :app modules we
  copied no longer exist there and packages became com.metrolist.shared.*. Its shared/commonMain code (listen together,
  settings, lyrics, Last.fm) is the place to port new features from. YouTube fixes arrive through the innertubex
  library (com.github.MetrolistGroup.innertubex): bump its version in gradle/libs.versions.toml and run ./check.sh.

Building
  ./gradlew :daemon:installDist     the daemon
  ./check.sh                        daemon tests + build, then cargo check for the client

Known gaps
  - Not ported yet: Room database + SyncUtils (library sync/history), listen-together. Music recognition is intentionally dropped.
  - PoToken: upstream mints it in an Android WebView; the stub returns none. Streams resolve through clients that do
    not need one; bridge to the login helper's webview if that stops working.
  - Spotify: sign-in uses the web-player sp_dc/TOTP route (BitChord's). BitChord's constants (query hashes) drift; the daemon
    reads fresh values from the live bundle for the token and profile, but SpotifyLibrary (vendored) uses its own hard-coded
    hashes until the bitchord submodule is bumped.
  - Credentials are stored in ~/.config/serafin/credentials.json (mode 0600).
